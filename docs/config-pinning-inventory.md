## Search and classification

Commands used to locate candidates and verify the positive search class:

```sh
rg --files tests -g 'test*'
rg -n 'SKILL.md|skills/|hooks.json|routing.md|PROFILE|PROFILES|FIXTURE' tests --glob 'test*'
rg -n 'read_text|read_bytes|open\(|assert|grep|scan' tests --glob 'test*'
rg -n 'SKILL.md' tests/test_shipped_surface.py
```

The last command is the control: it matches the known instruction reader in test_shipped_surface.py. Candidate assertions were read with their setup, fixtures and implementation where needed. A recorded tool event is data, not configuration merely because it is JSON. Test-authored profiles are controlled inputs; complete captured instructions are recorded configuration. The usage fixture explicitly identifies its section headings as test labels. General documentation/diagram layout and executable source are outside the configuration definition.

Each removal row identifies one original assertion site; a looped assertion includes its bound alternatives in the original test. R6 applies wherever the test still has behavior or validity assertions. Pure wording tests are deleted only when no such assertion remains. No automated pinning detector is added.
