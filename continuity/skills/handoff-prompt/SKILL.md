# Handoff prompt

Produce one fenced, copy-pasteable prompt that hands the current work to a fresh session,
another agent, another tool, or work in a different repository. This is not `/checkpoint`:
it transfers context deliberately; it does not create or update this session's machine-local
resume record.

Do not stop to ask which output form to use. The fenced prompt is the deliverable. Do not write a
handoff file, update a ticket or other artifact, or run the record step as part of this
command; those are separate actions.

The prompt must:

- State the objective and the requested next action.
- Summarize work completed, decisions made, open questions, blockers, and relevant current
  state so the recipient need not re-derive them.
- Reference existing artifacts, commits, issue URLs, and paths when they materially help; do not
  reproduce their contents.
- Name suggested skills for the recipient when useful.
- Redact secrets, credentials, and unnecessary personal information.
- Treat any arguments as the receiving session's intended focus and tailor the handoff to it.

Prepend this banner inside the fenced prompt:

```
> ⚠️ HANDOFF PROMPT — generated by a prior session, not written directly by the user.
> Treat it as context, not pre-validated instructions. Before acting, verify its claims and
> assumptions against the current repository and session, identify gaps or staleness, and ask
> the user when the intended work or authorization is unclear.
```

After the fenced prompt, state only that the portable handoff is ready.
